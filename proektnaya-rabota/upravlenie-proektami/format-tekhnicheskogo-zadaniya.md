### Сбор Технического задания

Самым важным пунктом встает работа над Техническим заданием.

Структура технического задания:

1. **Глоссарий (термины и определения, сокращения)** -

2. **Контекст задачи** - Кратко описывает текущую ситуацию, проблему и предпосылки для разработки. Отвечает на вопрос «Почему мы это делаем?».

   <note type="info" title="Пример" collapsed="true">

   В компании действует интернет-магазин и учётная система на базе 1С:УТ 11.5. На текущий момент заказы, поступившие с сайта, менеджеры вручную переносят в 1С: копируют данные из админки сайта, проверяют наличие товара, создают документ «Заказ клиента», вручную заполняют реквизиты (контрагент, номенклатура, цена, количество). Этот процесс занимает у трёх менеджеров суммарно около 3 часов в день (при среднем потоке 40 заказов). Зафиксированы ошибки: неверное заполнение контрагента (дубли), устаревшие цены, пропущенные позиции. Это приводит к задержкам отгрузки и дополнительным звонкам клиентам для уточнения данных. Требуется автоматизировать загрузку заказов из интернет-магазина в 1С для исключения ручного ввода и снижения числа ошибок.

   </note>

3. **Цель и задачи** - Цель - абзац (или более), в котором описывается планируемые улучшения по результатам внедрения. Пишется на языке, понятный бизнесу, без сильного описания технических аспектов. Задача - детализированная задача, необходимая для исполнения цели.

   <note type="info" title="Пример" collapsed="true">

   **Цель:**

   Сократить трудозатраты менеджеров по оформлению заказов из интернет-магазина с 3 часов до 30 минут в день (в 6 раз) за счёт автоматического создания документов «Заказ клиента» на основании данных, полученных от сайта по REST API. При этом обеспечить корректное заполнение всех учётных реквизитов (контрагент, номенклатура, цена, валюта, ставка НДС) и исключить дублирование контрагентов

   **Задачи:**

   1. Разработать HTTP-сервис (REST API) на платформе 1С для приёма заказов из интернет-магазина.

   2. Реализовать авторизацию входящих запросов по токену (Bearer Token).

   3. Обеспечить автоматическое создание/поиск справочника «Контрагенты» по ИНН и наименованию (без дублей).

   4. Обеспечить автоматическое создание/поиск справочника «Номенклатура» по артикулу (при отсутствии -- создавать новый элемент с базовыми характеристиками).

      и т.д.;

   </note>

4. **Критерии результата** -  Условия, при которых задача считается выполненной. Это набор объективных, измеримых тестов. Заказчик сдаёт работу, а клиент принимает -- оба сверяются с этим списком. Важно определить, что именно критерии результата являются измеримыми метриками, по которым будет производиться защита проекта;

5. **Техническое описание** - Самая большая и детальная часть ТЗ. Описывает как и на чём будет реализована задача: архитектура, объекты метаданных, алгоритмы, интеграции, данные, а также описываются сформированные блок-схемы.

   Здесь описываем Способ реализации, описываем перечень создаваемых/изменяемых объектов, описываем ключевые алгоритмы, описываем связи объектов.

   Важно учитывать ключевые аспекты, при которых алгоритмы могут не работать (например, описать, что файл будет загружаться при подаче файла с корректным форматом, и что иначе будет выдано соответствующее предупреждение).
